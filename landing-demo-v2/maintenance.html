② 三个组件的技术栈与分工

每个组件独立可开发、独立可发版、独立可回滚

📦
install.sh / .ps1
Bash · PowerShell
技术栈
  • POSIX Shell（Mac/Linux）
  • PowerShell 5+（Windows）
  • 零外部依赖（curl 系统自带）
发布方式
  • 托管于 pangolinfo.dev/install
  • 每次 push 自动部署
  • 支持版本回滚 install.sh?v=1.0.2
变更频率
  • 初次开发后 几乎不动
  • 仅在新增 Agent 时加 case 分支
🧠
Skills
Markdown · YAML frontmatter
技术栈
  • 纯 Markdown 文档
  • YAML frontmatter 元数据
  • Python 辅助脚本（可选）
发布方式
  • GitHub Release tar.gz
  • 语义化版本（v1.2.0）
  • 用户 pangolinfo update 一键升级
变更频率
  • 最频繁——业务方法论持续迭代
  • 建议每 2 周一个 minor 版本
⚡
MCP Server
TypeScript / Python · stdio + SSE
技术栈
  • TypeScript + MCP SDK
  • 编译为单文件二进制（pkg / esbuild）
  • 三平台预编译（Mac/Linux/Win）
发布方式
  • GitHub Release 挂三平台二进制
  • npm 同步发布（可选）
  • 语义化版本严格遵守
变更频率
  • 跟随 Pangolinfo API 变化
  • 新增 tool 时 minor 版
  • API 不兼容 major 版

③ 初次开发分阶段计划

9.5 天工作量按"由内向外"顺序铺开，每阶段都有可演示交付物

Phase 1
Day 1-2

三线并行启动：骨架 + MCP × 3 + 双语落地页

交付：pangolinfo.dev 上线、3 个 MCP server 雏形跑通、中英双语落地页第一稿
  • 注册域名 pangolinfo.dev，Vercel 部署、配置 CDN 和 CNAME
  • 创建 GitHub Org 和 3 个独立仓库（skills / mcp-server / installer），LICENSE / Issue 模板齐全
  • 并行启动 3 个 MCP server：amazon-scraper / ai-serp / wipo，第一个跑通模式后另两个套用
  • 落地页中英双语版同步推进：SEO meta、Open Graph、Twitter Card 完整配置
  • 对接 Pangolinfo 现有注册接口（已就绪，无需后端配合）
Phase 2
Day 3-4

MCP 联调 + 安装脚本主框架 + 三选一交互

交付：3 个 MCP server 跨平台编译完成、Claude Code 一行命令装好全套（支持 Skills/MCP/Both 三种安装模式）
  • 3 个 MCP server 用 pkg 打包成 Mac / Linux / Windows 三平台二进制
  • install.sh 主框架：9 选 1 Agent 菜单 + 3 选 1 安装范围菜单（Skills only / MCP only / Both）
  • 三种安装路径独立实现：Skills 单独可工作、MCP 单独可工作、组合最佳
  • Claude Code 分支：Skills 下载解压 + MCP 注册到 ~/.claude.json
  • API Key 终端内注册（仅当用户选了 MCP 才触发）：问 Key → 邮箱 → 验证码 → 密码 → 写入 .zshrc
  • 触点 1-4 上线（落地页、Banner、安装过程、完成引导）
Phase 3
Day 5-6

Cursor + Cline + 4 个本地 Agent 全适配

交付：6 个本地 Agent 全部 Skills + MCP 自动安装；触点 5 延迟引导上线
  • Cursor、Cline 分支：Skills 拷贝 + MCP 注册到 IDE settings
  • Hermes、Windsurf、Codex、OpenClaw 四家分支：路径检测 + 配置文件改写
  • 触点 5 延迟引导：CLI 使用次数追踪 + 第 10 次弹"觉得有用？给个 Star"提示
  • 落地页 9 个 Agent 手风琴面板内容全部定稿（中英双版）
  • "小张故事"互动版加入落地页，非技术用户友好
Phase 4
Day 7-8

网页端 + Windows 完整版 + 埋点系统

交付：install.ps1 完整 Win 支持、ZIP 打包给网页端、埋点数据上报和看板
  • install.ps1 Windows 完整版：含 PowerShell 终端内注册、PSCredential 安全输入
  • Claude.ai / ChatGPT GPTs 分支：自动打包 ZIP 到 ~/Downloads + 落地页 GIF 上传引导
  • 埋点系统：安装漏斗（每步成功率）、Agent 选择分布、MCP 调用量、用户留存
  • 接入 PostHog 或自建轻量上报；管理后台可视化看板（每日核心指标）
  • 其他 Agent 通用方案文档完善，路径速查表对外
Phase 5
Day 9-10

CI/CD + 跨平台联调 + 正式发布

交付：三平台自动化测试上线、v1.0.0 首发、中英双语推广启动
  • GitHub Actions 配置 Mac / Ubuntu / Windows 三平台自动化测试矩阵
  • Release Workflow：tag 推送自动编译 3 个 MCP server × 3 平台 = 9 份二进制
  • 找 5-10 个真实用户试装收反馈（含 Windows 用户），修关键 bug
  • Twitter / 小红书 / V2EX / Hacker News 中英双语发文；申请 awesome-mcp、awesome-claude 收录
  • 埋点看板正式接入，发布后实时观察安装漏斗

④ 后期维护成本拆解

每个组件的月维护工时不同——按"业务变化频率"分配精力

维护项 触发条件 月均工时 风险等级
Skills 内容 方法论迭代 业务策略变化、新功能补充 0.5d 低
MCP Server 跟随 API 变化 Pangolinfo API 新增 / 调整字段 0.4d 中
install.sh 兼容性修补 某个 Agent 改了配置文件路径 0.2d 低
用户 issue 响应 "装不上"、"调用失败"等 0.3d 中
跨平台回归测试 每次发版前自动跑（CI） 0.1d 低
合计 — 1.5d / 月 —

⑤ 三种更新场景怎么处理

不同变化触发不同的发布流程，用户感知的更新成本不同

📝 Skills 方法论更新

频率：每 2 周 · 用户：无感知
改 Markdown 文档，提交 PR。CI 自动验证 frontmatter 格式，merge 后自动打 tar.gz 挂 Release。
# 用户主动更新（可选） pangolinfo update # 或重新跑安装脚本（幂等）

⚡ MCP Server 升级

频率：每月 1 次 · 用户：提示升级
改 TypeScript 代码，CI 自动跨平台编译三个二进制，挂 Release。Server 启动时检查最新版，提示用户升级。
# Server 启动时自检 pangolinfo-mcp --check-update # 升级 pangolinfo upgrade

🛠️ 新增 Agent 支持

频率：偶尔 · 工时：0.5d / 个
在 installer/agents/ 新增一个 sh 文件，定义该 Agent 的目录路径和配置写法。落地页手风琴加一项。不影响存量用户。
# 新增 Agent 的最小代码 case $agent in 10) install_new_agent ;; esac

🚨 紧急 Bug 修复

频率：极少 · 响应：2-4 小时
通过 patch 版本快速发版。install.sh 用户重跑即可，MCP server 用户提示升级。GitHub Issue 公开追踪。
# Hotfix 流程 git checkout -b hotfix/x.y.z # 修复 → CI → Release

⑥ 线上监控与问题排查

出问题时怎么发现、怎么定位——降低用户报 issue 后的响应时间

📊
安装成功率
install.sh 内置上报
采集指标
  • 用户 OS / Agent 选项分布
  • 每一步骤的成功/失败
  • 失败时的错误信息（脱敏）
响应动作
  • 失败率超过 5% 自动告警
  • 定位是哪个 Agent / 哪步出问题
  • 24h 内 hotfix 上线
🔍
MCP 调用日志
Server 端日志收集
采集指标
  • 每个 tool 的调用次数 / 失败率
  • 响应时间 P50/P95/P99
  • Key 鉴权失败次数
响应动作
  • P95 > 3s 告警，可能是 API 限流
  • Key 失败率高 → 主动联系用户
  • 热门 tool 优化优先级最高
