三个需要正视的风险点

都有成熟解决方案，但不能装作不存在。

⚠️ Windows 平台需要单独维护

Windows 11 自带 curl，但默认 PowerShell 不是 bash，| sh 跑不了。 需要同时提供 .ps1 脚本：irm pangolinfo.dev/install.ps1 | iex

影响 脚本工作量翻倍（要写两套），但 PowerShell 完全能实现同样效果。国内 Windows 用户占比高，必须做。

🔧 管道模式下 stdin 处理

curl | sh 时 stdin 被占用，"按回车确认"这类交互读不到键盘。

解决 所有 read 命令显式重定向：read key < /dev/tty。 这是 rustup / Homebrew / Ollama 的标准做法，社区方案成熟。

🛡️ curl|sh 的安全顾虑

部分用户（尤其企业 / 安全意识强的开发者）会拒绝 curl | sh。

解决 README 平铺多种方式：npm、git clone、可审计的两步式 curl、一行命令。让用户按信任级别自选。
